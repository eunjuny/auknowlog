# 쿠버네티스 심층 퀴즈
총 9문항 · 정답 9 · 오답 0

## Q1. 쿠버네티스 API를 확장하여 클러스터에 새로운 종류의 오브젝트를 정의할 수 있게 해주는 기능은 무엇인가요? 이를 통해 쿠버네티스 네이티브 방식으로 사용자 정의 리소스를 관리할 수 있습니다.
- A. Service Mesh
- B. Operator
- C. Custom Resource Definition (CRD)
- D. Admission Controller
✅ 내 답: Custom Resource Definition (CRD)
설명: CRD는 개발자가 자체 API 오브젝트를 정의하고 쿠버네티스 API 서버가 이들을 처리하도록 함으로써 쿠버네티스 기능을 확장할 수 있게 합니다.

## Q2. 특정 작업을 한 번만 실행하거나, 주기적으로 정해진 시간에 실행해야 하는 배치 작업이나 스케줄링된 작업을 위해 설계된 쿠버네티스 리소스는 무엇인가요?
- A. Deployment
- B. StatefulSet
- C. Job
- D. DaemonSet
✅ 내 답: Job
설명: Job은 한 번 성공적으로 완료되면 종료되는 파드를 생성하는 데 사용됩니다. CronJob은 Job을 주기적으로 실행하도록 스케줄링하는 데 사용됩니다.

## Q3. 쿠버네티스에서 'Namespace'의 주요 용도는 무엇인가요?
- A. 클러스터 노드를 그룹화
- B. 클러스터 내 리소스를 격리하고 조직화
- C. 파드 간의 네트워크 통신 암호화
- D. 애플리케이션 로그를 수집
✅ 내 답: 클러스터 내 리소스를 격리하고 조직화
설명: 네임스페이스는 여러 사용자가 하나의 클러스터를 공유할 때 리소스 간의 충돌 없이 작업을 수행할 수 있도록 리소스를 격리하는 데 사용됩니다.

## Q4. 'ReplicaSet'이 보장하는 주요 기능은 무엇인가요?
- A. 컨테이너 이미지를 자동으로 빌드
- B. 명시된 수의 파드 복제본이 항상 실행되도록 보장
- C. 클러스터 간에 데이터를 복제
- D. 파드에 대한 외부 접근을 제어
✅ 내 답: 명시된 수의 파드 복제본이 항상 실행되도록 보장
설명: 레플리카셋은 항상 지정된 수의 파드 복제본이 실행되도록 유지함으로써 고가용성과 스케일링을 지원합니다.

## Q5. 'ConfigMap'의 주요 용도는 무엇인가요?
- A. 민감한 정보를 저장 (예: 비밀번호)
- B. 애플리케이션 구성을 키-값 쌍으로 저장
- C. 영구 스토리지를 제공
- D. 클러스터 노드의 건강 상태를 모니터링
✅ 내 답: 애플리케이션 구성을 키-값 쌍으로 저장
설명: ConfigMap은 코드와 비민감성 구성 데이터를 분리하여 애플리케이션 구성을 관리하는 데 사용됩니다.

## Q6. 쿠버네티스에서 'Secret'의 주요 용도는 무엇인가요?
- A. 파드의 로그를 수집
- B. 민감한 정보를 암호화된 형태로 저장 (예: API 키, 비밀번호)
- C. 네트워크 정책을 정의
- D. 애플리케이션 스케일링을 관리
✅ 내 답: 민감한 정보를 암호화된 형태로 저장 (예: API 키, 비밀번호)
설명: Secret은 비밀번호, OAuth 토큰, SSH 키와 같은 민감한 정보를 저장하는 데 사용되며, Base64로 인코딩되어 저장되지만 기본적으로 암호화되지는 않습니다.

## Q7. 쿠버네티스에서 컨테이너 간의 네트워킹을 구현하기 위한 플러그인 인터페이스 표준은 무엇인가요?
- A. CRI (Container Runtime Interface)
- B. CSI (Container Storage Interface)
- C. CNI (Container Network Interface)
- D. CPI (Cloud Provider Interface)
✅ 내 답: CNI (Container Network Interface)
설명: CNI는 쿠버네티스 클러스터 내에서 컨테이너 네트워킹을 구성하기 위한 표준화된 인터페이스를 제공합니다.

## Q8. 쿠버네티스의 주요 이점 중 하나로, 애플리케이션의 수요에 따라 파드 수를 자동으로 조정하는 기능은 무엇과 관련이 있나요?
- A. 보안 (Security)
- B. 확장성 (Scalability)
- C. 지속적 통합 (Continuous Integration)
- D. 영구 스토리지 (Persistent Storage)
✅ 내 답: 확장성 (Scalability)
설명: 쿠버네티스는 Horizontal Pod Autoscaler(HPA)와 같은 기능을 통해 애플리케이션의 트래픽이나 리소스 사용량에 따라 자동으로 파드 수를 조정하여 확장성을 제공합니다.

## Q9. 쿠버네티스에서 애플리케이션을 새로운 버전으로 업데이트할 때, 서비스 중단 없이 점진적으로 변경사항을 적용하는 배포 전략은 무엇인가요?
- A. 블루/그린 배포 (Blue/Green Deployment)
- B. 카나리 배포 (Canary Deployment)
- C. 롤링 업데이트 (Rolling Update)
- D. 재생성 배포 (Recreate Deployment)
✅ 내 답: 롤링 업데이트 (Rolling Update)
설명: 롤링 업데이트는 새 버전의 파드를 점진적으로 배포하고 이전 버전의 파드를 점진적으로 종료하여 서비스 중단 없이 업데이트를 수행하는 전략입니다.
