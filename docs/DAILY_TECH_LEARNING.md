# 데일리 기술 학습

## 목적

기술 기사를 단순 요약으로 소비하지 않고, 기사 맥락에서 필요한 개념을 설명한 뒤 복습과 심화 학습으로 연결합니다. 기사 전문은 저작권과 출처 정책을 고려해 화면에 재게시하지 않고 원문 링크와 자체 요약·보충 해설을 제공합니다.

## 생성 흐름

```text
07:30 Asia/Seoul 스케줄러
  → 설정된 RSS 기사 후보 수집
  → 개발 직접 관련 → 개발 인접 → IT 확장 순서로 선택
  → URL 안전 검증(사설망/리다이렉트/크기 제한)과 본문 추출
  → OpenAI Structured Outputs: 요약·보충 해설·핵심 개념·복습 문항 수
  → source_document + daily_learning 저장
  → 화면에서 복습 문제 시작(기존 퀴즈 API)
  → 서버 채점·풀이 기록·오답 복습 예약
  → 복습 퀴즈 제출 시 daily_learning COMPLETED
```

## 비용과 중복 방지

- 기사 선택은 제목·RSS 설명·카테고리의 키워드를 서버에서 점수화합니다. `DEVELOPER_CORE`(백엔드·DB·클라우드·DevOps·보안·오픈소스 등)를 가장 먼저, 없을 때 `DEVELOPER_ADJACENT`(LLM·AI 운영·데이터센터·네트워크 등), 그 다음 `IT_EXPANSION`(반도체·로봇·통신 등)을 선택합니다. 이 단계는 OpenAI를 호출하지 않습니다.
- 화면은 선택된 등급을 `개발 핵심`, `개발 인접`, `IT 확장`, `직접 선택`으로 표시합니다. 사용자가 URL을 직접 지정한 경우에는 RSS 분류를 덮어쓰지 않습니다.
- 같은 등급 안에서는 제목의 관련 키워드 수, RSS 설명·카테고리의 관련 키워드 수, 발행 시각 순서로 선택합니다. 키워드는 우선순위를 보장하는 초기 정책이며, 기사 본문 품질·개발자 효용을 완전히 판정하는 AI 분류기는 아닙니다.
- 해설 생성은 하루·기사 URL별로 하나만 저장합니다. 같은 날짜의 스케줄 재시도와 수동 재시도는 기존 결과만 돌려줍니다.
- 해설 생성은 `daily-learning.max-output-tokens=3600` 및 전역 일일 토큰 예산을 함께 검사합니다.
- 복습 문항 수는 2~12개 사이에서 AI가 핵심 개념 수와 중요도에 맞게 결정합니다. 심화 문제는 사용자가 요청할 때만 생성합니다.
- RSS·URL 추출·DB 조회·서버 채점·Git 저장에는 OpenAI 비용이 없습니다.

## Git 노트

채점 후 Git 저장을 누르면 notes 원격에 다음 구조로 저장합니다.

```text
daily-tech/
└── 2026-09-22-기사_제목/
    ├── learning.md
    ├── review/
    │   └── 복습_주제.md
    └── advanced/
        └── 심화_주제.md
```

같은 주제 퀴즈를 다시 저장하면 `-2`, `-3`을 붙여 덮어쓰지 않습니다.

## 운영 한계

스케줄러는 로컬 Spring Boot 프로세스가 실행 중일 때만 동작합니다. 오전 생성 시점에 맥 또는 백엔드가 꺼져 있었다면 UI의 생성 버튼으로 재시도해야 합니다. 다중 인스턴스 클라우드 환경으로 옮길 경우에는 DB 기반 분산 락 또는 작업 큐를 추가해야 스케줄러 중복 실행을 막을 수 있습니다.
