## 작성 방향

공개된 백엔드 개발자 포트폴리오를 참고하되 문장이나 디자인을 복제하지 않았습니다. 다음 공통점을 이 프로젝트에 맞게 적용했습니다.

- 기술 목록보다 프로젝트를 시작한 이유와 실제로 발견한 문제를 먼저 설명합니다.
- 모든 기능을 같은 비중으로 나열하지 않고, 백엔드 판단이 드러나는 사례를 골라 자세히 설명합니다.
- 문제, 선택, 적용 범위와 검증 근거가 한 흐름으로 읽히게 구성합니다.
- 측정하지 않은 성능이나 효과를 만들지 않고 실패 가능성과 남은 과제를 함께 적습니다.

포트폴리오의 핵심 사례는 다음 세 가지입니다.

- 주제별 무작위 출제의 핵심 내용 누락을 `CORE`·`SUPPORTING` 학습 목표와 서버 커버리지 배정으로 줄인 경험
- SHA-256 정확 중복, pgvector 의미 중복과 임베딩 장애 폴백을 함께 설계하고 실제 PostgreSQL에서 검증한 경험
- AI 호출 원장과 Prometheus 지표를 분리해 요청 비용과 문제 채택·중복 제거 과정을 관측한 경험
- 실제 문제 쌍과 사람 판정을 별도로 저장해 pgvector 임계값의 정밀도·재현율을 계산하고, AI 목표 평가의 잠정 지표와 사람 검증 지표를 구분한 경험

## 근거와 표현의 경계

- 화면 이미지는 로컬 실행 화면에서 캡처했습니다. 문서 작업 중 새 AI 문제를 생성하지 않았습니다.
- 대시보드 수치는 로컬 DB의 최근 14일 기록입니다. 처리 용량이나 비용 절감 효과를 입증하는 부하 테스트 수치로 사용하지 않습니다.
- 테스트 수치는 2026-09-14에 로컬에서 `./gradlew check --rerun-tasks --no-daemon`을 실행한 결과 XML을 기준으로 합니다. 단위·H2 40개와 실제 pgvector 통합 3개, 총 43개가 통과했습니다.
- 로드맵 사례는 `CORE`·`SUPPORTING` 목표별 1~5문제 배정, 학습 단위 최대 30문제와 단일 생성 최대 20문제의 차이, `objectiveKey` 서버 검증과 V13 FK 저장을 함께 설명합니다.
- 실제 pgvector 테스트와 모킹 기반 임베딩 장애 테스트의 범위를 구분합니다. 고정 벡터 테스트가 한국어 의미 품질과 HNSW 성능까지 증명하지는 않습니다.
- Prometheus 집계 지표, PostgreSQL 기반 앱 대시보드, 선택형 Langfuse 추적을 구분합니다. Prometheus 화면은 2026-09-14 로컬 scrape target의 실제 `UP=1` 결과입니다.
- 임베딩 실패 시 해시 폴백, 제한된 보충 요청, 원본과 벡터의 저장 실패 가능성을 숨기지 않습니다.
- 미래 계획은 현재 구현한 기능과 구분합니다. 실사용 이메일, 인증정보, 개인 원격 URL을 넣지 않습니다.
- V14 품질 평가 화면을 포트폴리오에 반영할 때는 사람 검증 표본 수와 평가 주제 구성을 함께 표시하고, 표본이 없는 AI 잠정 수치를 성과로 표현하지 않습니다.

## 갱신 절차

1. 변경된 기능의 코드·설정·테스트와 기준 문서를 확인합니다.
2. 영향을 받는 포트폴리오 페이지를 수정하고, 실제 화면이 바뀌었으면 이미지를 다시 캡처합니다.
3. 편집본을 PDF로 변환한 후 전체 페이지를 이미지로 렌더링합니다.
4. 한글 글꼴, 잘림·겹침, 표, 화살표 방향과 페이지 번호를 육안으로 확인합니다.
5. 개인정보·시크릿 포함 여부와 수치의 기준일을 점검하고 두 산출물을 함께 갱신합니다.

현재 생성 소스와 캡처 원본은 로컬 `.portfolio-build/portfolio_human.mjs`와 `.portfolio-build/screenshots/`에 있습니다. 이 경로는 작업용이며, 외부 제출 대상은 위 산출물입니다. 자동 생성 소스는 Codex의 번들 Node 런타임과 artifact-tool을 사용하는 로컬 경로를 포함하므로 다른 환경에서는 경로 조정이 필요합니다. PPTX를 직접 편집할 수도 있습니다.
