# 프로젝트 포트폴리오 관리

## 목적과 작성 기준

이 포트폴리오는 이력서에 첨부하는 프로젝트 설명 자료입니다. 개인의 경력 연차와 자기소개를 제외하고, 프로젝트의 목적·기능·구조·데이터 흐름·기술 선택 이유를 존댓말로 설명합니다.

기능 설명의 기준은 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)입니다. 제출용 PDF는 2026-09-30에 확인한 구현과 실행 화면의 스냅샷이며, 기능 변경 후 자동으로 갱신되지는 않습니다.

## 산출물

- [제출용 PDF v19](../output/pdf/Auknowlog_Project_Portfolio_current-v19.pdf) — 현재 제출 기준

이전 v18 PPTX는 새 인증·관리자 장면이 반영되지 않아 현재 제출본으로 취급하지 않습니다. 이번 요청 범위에서는 PDF만 갱신했습니다.

## 작성 방향

공개된 백엔드 개발자 포트폴리오를 참고하되 문장이나 디자인을 복제하지 않았습니다. 다음 공통점을 이 프로젝트에 맞게 적용했습니다.

- 현재 서비스의 목적, 제공 기능, 전체 구조를 먼저 설명합니다. 초기 기능이나 수정 과정을 중심 서사로 사용하지 않습니다.
- 기능별 실제 화면 9페이지에 로컬 분리 환경의 Keycloak 로그인과 전체 관리자 화면 2페이지를 추가했습니다. 각 화면 옆에 사용자의 행동·화면에서 읽을 정보·서버 처리와의 연결을 설명합니다.
- 문제 생성, 의미 중복 검사, 목표 기반 학습, 데일리 학습, 서버 채점·복습과 관측의 현재 처리 흐름을 도식으로 보여줍니다.
- 기술은 계층별 역할과 선택 이유를 함께 설명하고, 선택 연동과 현재 사용하지 않는 기술을 구분합니다.
- 측정하지 않은 성능이나 효과를 만들지 않고 실패 가능성과 남은 과제를 함께 적습니다.

포트폴리오의 핵심 기술 주제는 다음과 같습니다.

- 주제별 무작위 출제의 핵심 내용 누락을 `CORE`·`SUPPORTING` 학습 목표와 서버 커버리지 배정으로 줄인 경험
- SHA-256 정확 중복, pgvector 의미 중복과 임베딩 장애 폴백을 함께 설계하고 실제 PostgreSQL에서 검증한 경험
- AI 호출 원장과 Prometheus 지표를 분리해 요청 비용과 문제 채택·중복 제거 과정을 관측한 경험
- 실제 문제 쌍과 사람 판정을 별도로 저장해 pgvector 임계값의 정밀도·재현율을 계산하고, AI 목표 평가의 잠정 지표와 사람 검증 지표를 구분한 경험
- OpenAI 호출 없이 고정 fixture로 브라우저 흐름을 재현하고, Node 22 CI에서 Vue 단위 테스트·빌드·Chromium E2E를 함께 실행한 경험
- Keycloak Authorization Code + PKCE, Spring Security JWT 검증, USER/ADMIN RBAC와 사용자별 학습 데이터 소유권을 V20으로 분리한 경험
- 전체 관리자 읽기 전용 API와 사용자별 조회 경계를 분리하고, V21 AI 사용자 귀속·임베딩 원장과 실제 OIDC 401/403/404/200 검증을 적용한 경험. [osc 추가 구현](OSC_ADDITIONAL_IMPLEMENTATION.md) 참고
- Vue·Nginx·Spring·PostgreSQL·Keycloak을 함께 띄운 분리 Compose에서 실제 Chromium 로그인을 수행하고, 테스트 전용 볼륨을 정리하는 CI 재현 절차. [인증·테넌시](AUTHENTICATION_AND_TENANCY.md), [컨테이너 실행](CONTAINER_RUNTIME.md) 참고

v19 PDF는 인증 화면, 관리자 화면, `owner_id` 데이터 경계와 401/403/404/200 검증을 반영합니다. 관리자 화면의 수치는 별도 테스트 DB의 샘플로, 실제 운영 성능이나 비용을 뜻하지 않습니다. V22의 관리자 감사·동시 AI 예산 예약/정산·사용자별 학습 메일 대기열/재시도는 [ACCOUNT_OPERATIONS.md](ACCOUNT_OPERATIONS.md)에 설명되어 있으나, 이번 PDF에 상세 화면·경쟁 테스트·SMTP 모의 검증까지 모두 담은 것은 아닙니다.

## 근거와 표현의 경계

- 기존 기능별 9개 화면은 2026-09-29 로컬 Vue 화면과 실제 백엔드 조회 결과를 캡처했습니다. 촬영 브라우저는 `/api/`의 GET 외 요청을 차단했고, 새 AI 문제·임베딩 생성과 풀이·복습 상태 변경은 수행하지 않았습니다. 표지의 모바일 이미지는 기존 캡처입니다.
- 추가된 2개 화면은 2026-09-30 분리된 컨테이너 환경에서 캡처한 빈 Keycloak 로그인과 테스트 전용 관리자 화면입니다. 계정·비밀번호·토큰을 담지 않았고, AI·SMTP 호출은 비활성화했습니다. 샘플 수치는 별도 DB의 고정 데이터입니다.
- 화면은 가독성을 위해 관련 영역을 발췌했습니다. 데일리 학습은 이번 촬영에서 새로운 기사를 생성하지 않고 기존 구현 근거의 흐름도로 설명합니다. 과거 풀이 기록에 보기별 해설이 없는 경우 전체 해설만 표시되는 제약을 해당 페이지에 명시합니다.
- 대시보드 수치는 로컬 DB의 최근 14일 기록입니다. 처리 용량이나 비용 절감 효과를 입증하는 부하 테스트 수치로 사용하지 않습니다.
- 백엔드는 `./gradlew check`로 단위·H2와 실제 pgvector Testcontainers 검증을 분리합니다. 프론트엔드는 `npm run test`, `npm run build`, `npm run test:e2e`를 별도 실행합니다. 제출용 문서에는 실행 시점·결과를 함께 기록하고, 실패하지 않은 테스트 수를 임의로 합산하지 않습니다.
- 로드맵 사례는 `CORE`·`SUPPORTING` 목표별 1~5문제 배정, 학습 단위 최대 30문제와 단일 생성 최대 20문제의 차이, `objectiveKey` 서버 검증과 V13 FK 저장을 함께 설명합니다.
- 실제 pgvector 테스트와 모킹 기반 임베딩 장애 테스트의 범위를 구분합니다. 고정 벡터 테스트가 한국어 의미 품질과 HNSW 성능까지 증명하지는 않습니다.
- Prometheus 집계 지표, PostgreSQL 기반 앱 대시보드, 선택형 Langfuse 추적을 구분합니다. AI 운영 화면은 DB 원장을 표시하며 Prometheus 화면으로 설명하지 않습니다. 다음 페이지에서 두 저장·조회 경로를 도식으로 구분합니다.
- 임베딩 실패 시 해시 폴백, 제한된 보충 요청, 원본과 벡터의 저장 실패 가능성을 숨기지 않습니다.
- 미래 계획은 현재 구현한 기능과 구분합니다. 실사용 이메일, 인증정보, 개인 원격 URL을 넣지 않습니다.
- V14 품질 평가 화면을 포트폴리오에 반영할 때는 사람 검증 표본 수와 평가 주제 구성을 함께 표시하고, 표본이 없는 AI 잠정 수치를 성과로 표현하지 않습니다.
- Playwright는 실제 Chromium과 Vite 화면을 사용하지만 API는 고정 fixture로 대체합니다. 서버 채점·정답 비공개·복습 예약 계약은 Spring 통합 테스트가 검증한다는 경계를 슬라이드에도 명시합니다.

## 갱신 절차

1. 변경된 기능의 코드·설정·테스트와 기준 문서를 확인합니다.
2. 영향을 받는 포트폴리오 페이지를 수정하고, 실제 화면이 바뀌었으면 이미지를 다시 캡처합니다.
3. 편집본을 PDF로 변환한 후 전체 페이지를 이미지로 렌더링합니다.
4. 한글 글꼴, 잘림·겹침, 표, 화살표 방향과 페이지 번호를 육안으로 확인합니다.
5. 개인정보·시크릿 포함 여부와 수치의 기준일을 점검하고 요청 범위의 산출물을 갱신합니다.

v19 PDF는 로컬 작업용 `.portfolio-build/portfolio_v19_pdf.py`에서 v18 PDF의 아키텍처·기술 페이지를 교체하고 인증 3페이지를 추가해 생성했습니다. 기능별 기존 캡처는 `.portfolio-build/screens-v17/`, 새 인증 캡처는 `.portfolio-build/screens-v19/`에 있습니다. 이 경로는 작업용이며, 외부 제출 대상은 위 PDF입니다. 생성 스크립트는 기존 v18 PDF와 캡처를 입력으로 사용하므로 독립 빌드 소스로 간주하지 않습니다. 재현 가능한 편집 소스 정리는 후속 과제입니다.
