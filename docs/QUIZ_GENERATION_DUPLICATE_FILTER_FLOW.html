Overview

1

2

같은 주제 최근 30개
3

GPT 생성

구조화된 문제 후보
4

정확 중복

정규화 + SHA-256
5

의미 중복

임베딩 + pgvector

세 겹의 방어선
생성 전에는 최근 문제를 GPT에게 알려 중복 가능성을 낮추고, 생성 후에는 SHA-256으로 동일 표현을, 임베딩이 활성화된 경우 pgvector로 의미가 비슷한 표현을 다시 검사합니다.

01 · Client request

사용자가 “쿠버네티스 5문제”를 요청한다

Vue 화면은 입력 상태를 초기화하고 실제 AI 모드에서 생성 API를 호출합니다.

Vue
주제: 쿠버네티스→ 문제 수: 5→ AI 모드 선택→ POST /api/quizzes/create
Controller
topic 필수·최대 120자→ 문제 수 1~20→ 미지정 시 5개
Service
topic.trim()→ 목표 개수 targetCount = 5→ collectedQuestions = []

학습 자료가 없는 경우

주제만으로 문제를 생성하고 sourceReferences는 빈 배열로 받습니다.

학습 자료가 있는 경우

먼저 /api/sources에 자료를 저장하고 반환된 sourceId의 청크를 퀴즈 생성 근거로 전달합니다.

화면의 “비용 없는 데모 퀴즈”가 켜져 있으면 /api/quizzes/dummy를 호출하므로 GPT 생성과 중복 필터링 경로를 지나지 않습니다. 실제 AI 흐름은 해당 옵션을 해제했을 때 실행됩니다.

02 · Generate candidates

최근 문제를 먼저 보여주고 후보를 생성한다

첫 번째 생성 라운드에서만 같은 주제의 최근 이력을 프롬프트에 포함합니다.

1

최근 문제 조회

findByTopic("쿠버네티스") 결과를 최신순으로 정렬하고 최대 30개를 선택합니다.

2

토큰 절약

문제 전체가 아니라 각 문제의 앞 50자만 GPT 프롬프트에 넣습니다.

3

GPT 후보 생성

gpt-5.4-mini에 정확히 5개의 객관식 문제를 구조화된 JSON으로 요청합니다.

Create a multiple-choice quiz with exactly 5 questions. Use the same language as the topic. <topic> 쿠버네티스 </topic> Create questions materially different from these existing questions: <existing_questions> - 쿠버네티스에서 Pod의 역할은 무엇인가요?... - Deployment와 StatefulSet의 차이는 무엇인가요?... ... 최대 30개, 각 50자 </existing_questions>
최근 문제 전달은 “생성 전에 중복을 피하도록 유도”하는 장치입니다. GPT가 지시를 완벽히 지킨다고 가정하지 않기 때문에, 응답을 받은 뒤 서버에서 각 문제를 다시 검사합니다.

03 · Filter every question

후보 문제를 하나씩 통과시킨다

한 개라도 조건을 통과하지 못하면 해당 후보만 버리고 다음 후보를 검사합니다.

A

응답 구조 검증

요청한 후보 개수, 문제 문장, 서로 다른 선택지 4개, 선택지와 일치하는 정답, 해설을 확인합니다.

응답 전체 거절 가능
B

SHA-256 정확 중복 검사

소문자화·공백 제거 전에 ++ → plusplus, # → sharp 등을 치환하고 64자리 해시를 조회합니다.

같은 해시 → 후보 제외
C

OpenAI 임베딩 생성

정확 중복이 아니면 문제 문장 하나를 text-embedding-3-small로 보내 512차원 벡터를 받습니다.

비활성·장애 → 다음 단계 생략
D

pgvector 의미 중복 검색

기존 벡터 중 코사인 유사도가 가장 높은 문제를 찾고 0.90 이상인지 검사합니다.

0.90 이상 → 후보 제외
E

문제·벡터 저장

question_history에 원문과 해시를 저장하고, 검사에 사용한 벡터를 재호출 없이 question_embedding에 저장합니다.

통과 → 수집 목록 추가
임베딩 장애가 퀴즈 전체 장애는 아닙니다.
API 키·네트워크·한도 문제로 임베딩이 실패하면 의미 검사는 건너뛰지만 SHA-256과 DB UNIQUE 제약은 계속 적용합니다.

04 · Concrete simulation

5개 중 2개가 중복이면 왜 4개를 더 요청할까?

보충 요청에서도 다시 중복이 나올 수 있으므로 필요한 개수의 두 배를 후보로 요청합니다.

1차 생성

목표 5개 → GPT에 5개 요청

attempt 1 / 3
Q1Pod 생명주기저장
Q2기존 문장과 동일해시 중복
Q3표현만 바꾼 기존 문제의미 중복
Q4Service 유형저장
Q5ConfigMap과 Secret저장
수집 3개 remaining = 5 - 3 = 2
→

2차 보충 생성

부족 2개 → GPT에 4개 요청

attempt 2 / 3
Q6Readiness Probe저장
Q7Resource Limit저장
Q8추가 후보목표 달성
Q9추가 후보검사 중단
requestedCount = min(remaining × 2, 20) = min(2 × 2, 20) = 4 수집 3 + 추가 2 = 최종 5개

왜 정확히 2개만 요청하지 않나?

보충 후보 2개에서도 중복이 나올 수 있습니다. 4개를 받아 여유 후보를 확보하고 목표 5개가 되면 즉시 반복을 끝냅니다.

그래도 5개를 못 채우면?

생성 라운드는 최대 3회입니다. 그때까지 통과한 문제만 저장·반환하므로 결과가 5개보다 적을 수 있습니다.

최근 30개 문제 미리보기는 1차 GPT 요청에만 포함합니다. 2·3차 보충 요청에서는 다시 보내지 않지만, SHA-256과 pgvector 사후 필터는 모든 라운드의 모든 처리 후보에 계속 적용됩니다.

05 · Persist and render

통과한 문제를 저장하고 화면에 표시한다

중복 검색용 이력과 실제 퀴즈 풀이용 데이터는 목적이 달라 별도 테이블에 저장됩니다.

중복 이력 저장

question_history에 주제, 문제, 해시, 선택지, 정답과 해설을 저장합니다.

벡터 색인 저장

question_embedding에 512차원 벡터와 모델명을 저장합니다.

학습 퀴즈 저장

learning_quiz와 순서가 있는 learning_question을 저장하고 quizId를 발급합니다.

Vue 렌더링

응답을 quizResult에 넣고 문제·선택지 버튼을 v-for로 화면에 표시합니다.

HTTP 200 OK { "quizId": 42, "quizTitle": "쿠버네티스 퀴즈", "questions": [ { "questionText": "쿠버네티스에서 Readiness Probe의 역할은?", "options": ["...", "...", "...", "..."], "correctAnswer": "...", "explanation": "...", "sourceReferences": [] } // 최종 통과한 문제들 ] } Vue: quizResult.value = response.data 화면: quizResult.questions를 순서대로 렌더링
화면 표시 시에는 정답과 해설 데이터도 응답에 포함되지만, 사용자가 답안을 제출하기 전까지 Vue가 정답 영역을 숨깁니다. 풀이 이력 저장과 오답 복습 예약은 이후 사용자가 별도로 “풀이 기록 저장”을 눌렀을 때 실행됩니다.

06 · Boundaries

재시도, 비용, 보장 범위를 구분한다

“생성 라운드 재시도”와 “같은 HTTP 요청의 일시 장애 재시도”는 서로 다른 장치입니다.

구분발생 조건최대동작비용 가능성
생성 라운드중복 제거 후 목표 개수 부족3회부족분의 2배를 추가 후보로 요청추가 GPT·임베딩 호출
HTTP 재시도429, 502, 503, 5044회지수 백오프와 Retry-After를 사용요청 처리 여부에 따라 달라짐
임베딩 폴백임베딩 비활성 또는 호출 장애해당 후보마다의미 검사 없이 해시 검사만 유지실패 이후 추가 임베딩 비용 없음
DB UNIQUE동시 요청이 같은 해시 저장항상한 요청만 저장하고 나머지는 후보 제외없음
보장하는 것
동일 해시 저장 차단, 통과 후보만 반환, 응답 구조 검증, 임베딩 장애 시 핵심 생성 경로 유지
보장하지 않는 것
항상 정확히 5개 반환, 모든 의미 중복 탐지, 0.90 임계값의 절대적 정확성, 외부 API 무장애
실제 AI 모드에서는 GPT Responses API 비용이 발생하며, 임베딩이 활성화되면 SHA-256을 통과한 각 후보에 Embeddings API 비용이 추가됩니다. 이 문서 자체와 자동 테스트는 외부 API를 호출하지 않습니다.
