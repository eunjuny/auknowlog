# `.roadmap.json` 학습 로드맵 형식

## 형식 선택

단계별 학습 계획의 원본 형식은 `*.roadmap.json`으로 정한다. Mermaid는 단계 관계를 보기 좋게 그리는 표현 형식이지만, 완료 기준과 진행 상태를 안정적으로 검증·저장하는 데이터 계약으로 쓰기에는 모호하다.

JSON을 사용하면 다음 이점이 있다.

- 필드 타입, 필수값, 최대 길이와 지원 버전을 서버에서 검증할 수 있다.
- Git diff에서 단계와 선행 조건의 변경을 확인할 수 있다.
- 백엔드, 프론트엔드, AI 생성 기능이 같은 계약을 공유한다.
- Mermaid, 트리, 타임라인 같은 화면은 저장된 JSON을 기준으로 안전하게 파생할 수 있다.

## 파일 계약 v1.2

파일명은 반드시 `*.roadmap.json`이어야 하고 최대 크기는 128KB다. 기존 `1.0`과 `1.1`도 계속 읽을 수 있다. 신규 AI 생성 결과는 필수 학습 목표와 출제 커버리지를 표현하는 `1.2`를 사용한다.

| 필드 | 역할 | 제한 |
| --- | --- | --- |
| `version` | 파일 계약 버전 | 신규 파일은 `1.2` |
| `title` | 로드맵 이름 | 필수, 최대 120자 |
| `topic` | 전체 학습 주제 | 필수, 최대 120자 |
| `description` | 전체 목표 설명 | 선택, 최대 2,000자 |
| `durationWeeks` | 예상 학습 기간 | 1~52주 |
| `steps` | 순서가 있는 대주제 목록 | 실제 학습 범위에 맞게 구성, 절대 안전선 10개 |
| `steps[].key` | 다른 대주제가 참조하는 안정적인 식별자 | 영문·숫자·`-`·`_`, 최대 64자 |
| `steps[].topic` | 소주제가 없을 때 생성할 문제의 주제 | 선택, 비우면 전체 주제 |
| `steps[].questionTarget` | 소주제가 없으면 실제 목표, 소주제가 있으면 소주제 목표의 합 | 단독 학습 단위는 최대 30문제, 소주제 합계는 최대 300문제 |
| `steps[].dependsOn` | 먼저 완료해야 할 대주제의 `key` 목록 | 없는 대주제·자기 참조·순환 참조 금지 |
| `steps[].subtopics` | 대주제 아래에서 순서대로 진행할 소주제 | 선택, 실제 학습 범위에 맞게 구성, 대주제별 절대 안전선 10개 |
| `steps[].subtopics[].key` | 대주제 안에서 고유한 소주제 식별자 | 영문·숫자·`-`·`_`, 최대 48자 |
| `steps[].subtopics[].topic` | 해당 소주제 퀴즈를 생성할 구체적인 주제 | 선택, 비우면 대주제 주제와 소주제 이름을 조합 |
| `steps[].subtopics[].questionTarget` | 소주제를 완료하는 누적 풀이 문항 수 | 1~30문제, 개념 범위·난이도에 맞게 구성 |
| `learningObjectives` | 소주제가 없는 대주제 또는 각 소주제에서 검증할 구체적 목표 | 선택, 학습 단위당 최대 10개 |
| `learningObjectives[].key` | 문항과 목표를 연결하는 안정적인 식별자 | 영문·숫자·`-`·`_`, 최대 48자 |
| `learningObjectives[].title` | 사용자가 보는 핵심 내용 이름 | 필수, 최대 120자 |
| `learningObjectives[].description` | 학습 후 판단·설명할 수 있어야 하는 내용 | 선택, 최대 500자 |
| `learningObjectives[].importance` | 출제 우선순위 | `CORE` 또는 `SUPPORTING` |
| `learningObjectives[].targetQuestionCount` | 이 목표를 다뤄야 하는 문항 수 | 1~5문제 |

소주제가 없으면 대주제 하나가 그대로 학습 단계가 된다. 소주제가 하나 이상이면 대주제의 `questionTarget`은 각 소주제 목표의 합과 정확히 같아야 한다. 학습 목표가 있으면 해당 학습 단위의 `questionTarget`은 `targetQuestionCount` 합계와도 정확히 같아야 한다. 소주제가 있는 대주제에는 목표를 중복 정의하지 않고 각 소주제에만 둔다.

대주제와 대주제별 소주제는 각각 최대 10개이며, 펼친 전체 학습 단위는 최대 100개다. 각 학습 단위는 최대 30문제이므로 전체 로드맵의 이론적 절대 상한은 3,000문제다. 학습 목표별 최대 5문제와 단위당 최대 10개도 비정상 payload의 자원 고갈을 막는 안전선일 뿐 권장량이 아니다. AI는 주제 범위에서 빠뜨리면 안 되는 내용을 먼저 정하고, 그 내용을 검증할 수 있는 가장 작은 문제 수를 배정한다.

예제는 [Kubernetes 로드맵](examples/kubernetes.roadmap.json)에 있다.

## 실행 흐름

1. 사용자가 화면에서 대주제와 선택적 소주제를 작성하거나 `*.roadmap.json`을 선택한다. AI 생성은 먼저 저장되지 않은 편집용 미리보기로 반환한다.
2. 서버가 확장자, 크기, JSON 구조, 지원 버전과 대주제 의존성을 검증한다.
3. 소주제가 없는 대주제는 하나의 단계로, 소주제가 있는 대주제는 소주제별 단계로 펼친다.
4. AI는 각 실제 학습 단위에서 필수 개념·실무 판단을 `learningObjectives`로 만들고 중요도와 필요한 문항 수를 배정한다.
5. 같은 대주제의 소주제는 입력 순서대로 선행 관계를 자동 연결하고, 다음 대주제는 앞 대주제의 마지막 학습 단위에 연결한다.
6. AI 미리보기에서는 대주제·소주제와 학습 목표의 이름, 설명, 중요도, 순서, 문제 수를 수정할 수 있다. 사용자가 최종 저장을 누른 경우에만 편집한 JSON을 다시 검증한다.
7. 확인된 원본 JSON은 재현용으로 보관하고 단계·선행 관계·학습 목표는 PostgreSQL에 정규화해 저장한다.
8. 사용자가 학습을 시작하면 서버는 아직 목표 문항 수를 채우지 못한 `CORE` 목표를 먼저, 그다음 `SUPPORTING` 목표를 선택하고 한 목표에 치우치지 않도록 순환 배정한다.
9. 모델에는 `목표 키 + 설명 + 이번 요청의 정확한 문항 수`를 보내며, 각 응답 문항은 `objectiveKey`를 반환해야 한다. 서버는 목표별 개수와 단계 소속을 재검증한다.
10. 저장된 문항은 `learning_question.learning_objective_id`로 목표에 연결된다. 답안을 제출하면 목표별 출제 수와 정답 수가 갱신되고, 다음 생성은 남은 목표만 요청한다.
11. 모든 목표 문항 수에 도달하면 학습 단위가 완료되고 다음 소주제 또는 대주제가 열린다.

파일 가져오기와 직접 작성은 OpenAI API를 호출하지 않는다. AI 로드맵 생성은 주제 범위·난이도·자료 분량·기간을 기준으로 필요한 대주제와 소주제, 필수 목표와 목표별 문제 수를 정한다. 고정된 개수를 채우기 위한 주제 부풀리기·무작위 상식 문제·목표 중복을 금지하고, 생성 결과는 v1.2 편집 미리보기로 반환한다. `AI 미리보기 생성` 시점에만 모델 토큰을 사용하며, 편집 후 `최종 저장`은 OpenAI를 다시 호출하지 않는다. 저장 학습 자료를 선택한 경우에는 앞에서부터 최대 8개 청크를 근거 문맥으로 함께 보내고, 이후 해당 로드맵에서 만드는 퀴즈에도 같은 자료를 자동으로 연결한다.

`questionTarget`은 한 번의 API 응답 수가 아니라 해당 학습 단위를 완료하기 위한 누적 목표이며 최대 30문제다. 한 번의 퀴즈 생성 요청은 기존대로 최대 20문제이므로, 30문제 학습 단위는 최소 두 세션으로 나뉜다. 실제 생성에서 중복 필터링 등으로 목표보다 적은 문제가 반환되면 여러 학습 세션의 풀이 수를 누적해 완료한다.

## 출제 예시

`Pod` 소주제의 목표가 `생명주기 2문제`, `상태 프로브 2문제`, `장애 진단 1문제`라면 전체 완료 기준은 5문제다. 첫 세션에서 3문제를 요청하면 서버는 필수 목표를 우선해 `생명주기 1 + 상태 프로브 1 + 장애 진단 1`처럼 배정할 수 있다. 제출 후 두 번째 세션에서는 이미 다룬 수를 빼고 `생명주기 1 + 상태 프로브 1`만 요청한다. 모델이 생명주기 문제를 2개 반환하거나 알 수 없는 목표 키를 반환하면 저장 전에 실패 처리한다.

기존 v1.0/v1.1 로드맵처럼 `learningObjectives`가 없으면 이전의 주제 기반 생성 방식을 유지한다. 따라서 기존 데이터는 삭제하거나 강제 변환하지 않지만, 핵심 내용 커버리지와 목표별 진행률은 v1.2 로드맵에서만 보장한다.
